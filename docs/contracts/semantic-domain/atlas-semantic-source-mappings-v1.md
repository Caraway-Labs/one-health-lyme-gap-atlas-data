# Atlas semantic source mappings v1

Status: Story #192 implementation candidate for protected review. Owner: Atlas data stewardship and engineering. Registry: `atlas-semantic-source-mappings-v1.json`. Executable mapper: `src/lyme_gap_atlas_data/semantic_source_mappings.py`. Audited source matrix: `story-192-source-mapping-matrix-2026-09-24.md`.

The versioned registry binds an existing approved source family, exact product/vintage/definition version, owning measure, origin, native grain/time, and canonical or derived result field. It is deliberately a selector over governed outputs, not a source acquisition plan or a second ontology. Governed source-version UUID, approval state, run, artifact, checksum, record, and any normalization/eligibility proof come from a caller-supplied authority snapshot. The mapper rejects stale or incompatible tuples and then creates #190 observation and revision IDs, checks #191 exact metadata revision, constructs #193 lineage, and validates its authority joins. It never queries Snowflake, mutates existing rows, inserts a derived result into a canonical table, or adds an observation to the current release.

## Inputs and ownership

`map_record(record, metadata, authority, mappings)` accepts one selected, already validated canonical/release or derived result envelope. `record.source_output` is the actual owning output: the mapper reads the configured value field from it and checks native NEON identity, geography, time and normalization; selected derived result identity, inputs and evidence; or county/source-only scope. The remaining `record` fields supply the explicit #190 scope, strata and #193 authority edges, and must agree with the owning output. `metadata` is a complete #191 revision for the rule's measure. `authority` has the #193 source-version/run/artifact/record/proof/input/result maps assembled under existing role controls. `mappings` comes from `load_mapping_registry`. No field is filled from a similar source, a label, a retrieval date, or a current-release pointer.

For a selected derived output, the mapper requires its owning quality and limitations fields, and the #159 scientific eligibility field. The observation's quality, eligibility, and limitations references all point to the existing immutable owning `result_id`; their meanings remain in that result contract. A #158 result has no separate scientific eligibility field, so its eligibility reference identifies the owning result state and safe lineage rather than asserting a new eligibility determination. The mapper does not copy or reinterpret those fields.

The source governance ledger owns approval, source identity, product, vintage, definition version, run, and artifact. The canonical normalization registry owns exact-source tick IDs and mapping rules. #157 owns quality; #158/#159 own derivation, eligibility, evidence basis, limitations, and result revisions. #190 owns semantic identity and permitted states; #191 owns measure metadata; #193 owns lineage joins. The mapper only binds them. A field owner changing its authority requires review there before the mapping rule is updated.

The mandatory `steward_review.state` is `REVIEWED` for live mapping. #191's example metadata remains `PENDING`; a caller can pass `fixture_mode=True` only with `record.fixture=true` to exercise synthetic contract behavior. This test path does not approve a source or a metadata revision. When actual reviewed metadata and approved authority rows are unavailable, a live mapping fails rather than promoting synthetic evidence.

## Mapping and validation behavior

- The rule's source resource, optional scientific product/dataset, vintage, and source-definition version must agree with every source edge and the corresponding approved governance row. A globally valid source field cannot satisfy another source tuple.
- Exact #191 measure definition supplies the unit, denominator, allowed states, origin, grain, time and permitted strata. The input must repeat the expected field, indicator, unit and denominator. No conversion is implicit; the existing approved tick-registry conversion is separate and requires its own versioned proof.
- Tick strata supplied to a mapping must carry the existing normalization result. The mapper re-runs the exact publisher/product/version/source-value lookup and compares canonical ID, rule ID, registry ID and version. This rejects display labels, unlisted values, wrong products, and globally valid IDs without source-specific proof. The registry requires applicable strata for the NEON and selected derived examples.
- #190 enforces county FIPS only for county-native observations, native site/event IDs and `NOT_COUNTY_REPRESENTATIVE` for NEON, and null FIPS plus `UNKNOWN` for source-only evidence. The temporal scope must match the mapped measure. Publisher `No records`, zero, null, unknown, unavailable and not-defensible states remain distinct.
- #193 validates full source/run/artifact/record/proof joins, exact derived input sets, method and result revision, evidence basis, metadata revision, and optional release membership. The mapper does not infer scientific eligibility from lineage alone. The owning #158/#159 output must be validated before it is selected as an input.
- `map_records` rejects repeated semantic keys and revision IDs within a batch. A conflicting revision must be handled as separate immutable history under the owning contract, never overwritten in place.

The registry maps one selected #158 M1 prevalence shape and NEON active-collection #159 coverage/priority shapes. Other approved #158/#159 constructs retain their owning stores and require separately specified measure metadata and exact-source rules before a mapping is added. The fixed five-source county release remains authoritative for its existing 3,144 counties and 14 observations per county; V071/V072, V100–V102, current pointer and public views are unchanged. Its incidence floor is a two-source derivation whose physical observation currently pins the human source only; a future #190 adapter needs both human and SVI denominator lineage. Its state-unallocated slot has state-native meaning and cannot be projected into #190 v1's county grain. The matrix marks both semantic adapters deferred without changing historical release behavior. No new release is published. #194 owns service/public representations, and #195 owns generated cross-version and whole-release compatibility gates.

## Evidence boundary

The tests are synthetic contract fixtures over all eleven requested families, including native NEON canonical records produced by the current adapter and #158/#159 safe values produced by their owning serializers. The priority fixture uses the narrow #191 priority-method compatibility entry. They verify deterministic mapping and adversarial failures. They do not establish reviewed metadata, source-backed replay, approved Snowflake access, PROD/public publication, or a live consumer. Since this change adds no SQL, connector, storage, or deployment behavior, there is no new Snowflake integration claim. Existing county-release tests and hosted Quality check compatibility separately from the fixture evidence.
